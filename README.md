# 周报 / WEEKLY REPORT

Vue 3 + FastAPI + PostgreSQL 的小型周报系统。前端和 API 通过同一入口提供服务；周一为每周第一天。个人可编辑自己的任务与任务类型，所有登录用户可查看普通用户周报，并共同维护会议记录。

当前版本为 `v3.0.0`。

## 本地 Docker Desktop 启动

1. 复制 `.env.example` 为 `.env`，将 `POSTGRES_PASSWORD` 换成随机强密码，并把同一个密码填入 `DATABASE_URL`。密码若含 URL 保留字符，需要先进行 URL 编码。
2. 确认 `127.0.0.1:18080` 未被占用，然后在本目录执行：

   ```sh
   docker compose -p zhoubao-01a13375 up -d --build
   docker compose -p zhoubao-01a13375 ps
   ```

3. 创建第一位管理员：

   ```sh
   docker compose -p zhoubao-01a13375 exec api python -m app.bootstrap
   ```

   命令交互读取用户名、姓名及密码（至少 6 位），不会提供默认账号。随后打开 <http://127.0.0.1:18080>。

开发项目使用专属 Compose 名称、网络及数据库卷。数据库和 API 没有宿主机端口；其他 Compose 项目不会被启动、停止或清理。停止本项目使用 `docker compose -p zhoubao-01a13375 down`，该命令保留数据卷。**不要添加 `-v`，除非明确要删除本项目数据。**

## 开发和测试

前端在 `frontend/`：`npm ci`、`npm run build`、`npm test`。后端在 `backend/`：按 `requirements.txt` 安装依赖，设置 `DATABASE_URL`，执行 `alembic upgrade head`。浏览器测试在 `frontend/` 运行 `npm run test:e2e`，默认访问 `http://127.0.0.1:18081` 的专属测试项目。

测试数据库与开发数据库隔离：

```powershell
$env:APP_PORT = '18081'
docker compose -p zhoubao-01a13375-test -f compose.yaml -f compose.test.yaml up -d --build
```

测试数据库只绑定 `127.0.0.1:15433`。运行后端测试时，将 `.env` 中的数据库密码代入 `TEST_DATABASE_URL=postgresql+psycopg://zhoubao:<密码>@127.0.0.1:15433/zhoubao`，再从 `backend/` 运行 `python -m pytest -q`。浏览器测试前，把相同地址设置为 `DATABASE_URL`，运行 `python -m tests.seed_e2e`；此命令只重置测试数据库并建立三个测试账号。后端测试和浏览器种子程序都会拒绝非测试端口，以避免误清空其他数据库。

## 审查项目发版管理

在「审查配置」中给项目选择部署级别和网络。手工录入的项目需补齐 GitLab 实例地址和项目 ID。服务端将实例地址加入 `REVIEW_GITLAB_URLS`，再通过 `DEPLOYMENT_GITLAB_TOKENS` 配置只读 `read_api` 令牌。配置格式见 [.env.example](.env.example)。

启用后可在「升级计划」补录机房的当前版本和已知上线时间。补录基线或新增计划时，登记新版本须从 GitLab 查询结果选择分支，也可选择标签。补录多个既有版本时按版本号从低到高登记。新增计划可一次选多个机房，每个机房独立确认清单和实际上线结果。已确认的清单将检查任务派发到备忘作者的任务箱。

## 设计与数据约定

- 周标识是周一日期，格式 `YYYY-MM-DD`；工作日是 1–7 的数组（周一为 1）。
- 完成状态可为空；界面显示“未开始”，跨周复制时视为未完成。
- 任务类型包含六个所有人可选的内置类型，以及个人维护的类型。任务保存类型名称快照，字典改名或删除不修改历史任务；任务明细的任务名称是独立文本字段。
- 本周工作的任务明细存于 `tasks` 表。普通用户可修改服务器北京时间的当前周明细，管理员通过成员标签代管成员的当前和历史明细。
- 在本周工作点击「填写下周计划」，或从月历选择下一周，可新增、修改和删除个人任务计划。服务器按北京时间在计划周开始时锁定 `task_plans` 中的记录，访问计划周时生成独立的任务明细副本。原计划可在该周的「任务计划表（历史）」中查看。
- 个人任务看板包含任务箱、进行中和已完成。移列会同步当前周任务明细。跨周时，可在看板点「添加到本周工作」，也可在本周工作点击「添加进行中的任务」，批量添加当前周还未关联的进行中卡片。其他周仍有关联明细时，卡片只可移列或续做。
- 本周工作中新增任务或复制一行时，会同步创建独立的看板卡片。任务已有服务器当前周之前的明细时，名称、删除和转交会锁定，仍可填写当周任务进展和完成状态。
- 新建和编辑账号时可同时勾选“普通用户”和“管理员”，至少选择一个角色。新建默认勾选“普通用户”。修改角色会撤销该账号的会话。删除拥有管理员角色的账号前，须先移除管理员角色；删除后保留历史记录和用户名，并撤销会话。
- 用户状态默认为“正常”；管理员可改为“锁定”，锁定账号无法登录并提示“账号已锁定，请联系管理员。”，已有会话同步撤销。
- 同一账号滚动 5 分钟内第 6 次密码错误会自动锁定（用户名不区分大小写，成功登录不清除窗口内错误）。状态与计数持久化，锁定不会随时间自动解除；管理员改回“正常”后清空错误记录。用户管理会禁止停用、锁定或降级最后一位有效管理员。
- 新建用户及重置密码后的用户必须先修改初始密码，新密码不能与初始密码相同。拥有普通用户角色的账号可进入周报汇总、日历标记和 Excel 导出，也可接收转交任务和会议指派；同时拥有管理员角色的账号也适用。部署时执行 `alembic upgrade head` 将原有角色迁移为角色列表。
- 月历仅查询当前显示的六周任务标记；绿色 √ 表示该周有任务。会议记录对所有登录用户开放，按日期倒序分页，支持日期、内容及关联任务状态筛选。
- 自动保存具有修订号保护，遇到其他标签页修改时会提示冲突。
- 本周工作的任务卡片左上角提供拖拽手柄，上下拖动并松手后保存顺序，刷新及周报汇总按新顺序显示；手柄聚焦后也可用上下方向键移动。排序前先保存待提交的编辑，取消拖拽或原地放下不保存，保存失败时保留原顺序。
- 「本周任务进展」支持 `1.`、`1、`、`1)`、`(1)`、`（1）` 等单层数字编号，保留缩进、分隔符、空格及前导零。Enter 新增编号项（空项也继续新增），中间插入后原组后续编号自增，删除或剪切整项后递减；同格式、同缩进且原本连续的编号才属于同组，手动跳号和重新起号保持原文。
- Shift+Enter 在同一项内换行并缩进到正文位置；Backspace 在编号行行首或正文开头合并到同组上一项，后续编号递减，没有上一项时去掉编号；Delete 在项尾合并同组下一项。续行的格式缩进会在合并时去掉，数字位数变化后自动保持正文对齐。
- 在项目边界粘贴同格式连续清单时自动接入原组，其他粘贴保留原文。进展输入框支持文字拖放，并可通过 Ctrl/Cmd+Z、Ctrl+Y、Ctrl/Cmd+Shift+Z 撤销或重做，一次编辑和其编号重排一起恢复，最多保留 100 个动作。刷新、切周或加载外部替换内容后清空相应历史。
- 本周任务进展最多 5000 个 Unicode 字符。若编辑或自动重排后超限，整体拒绝该次操作并提示。中文组合输入确认后才应用重排和保存。

API 文档在登录后的 `/api/docs`；所有受保护的写请求需要 `X-CSRF-Token`，登录和 `/api/auth/me` 返回该值。新增、复制行及跨周复制支持 `Idempotency-Key` 请求头。

## 代码审查和消息中心

- 管理员在“审查配置”维护纳入日报的项目。项目别名默认用 GitLab 项目名，默认跳过名称带 `/` 的分支。项目删除后历史日报仍可查看。可将项目标记为常用，审查记录默认折叠非常用项目。部署需应用 `0012_review_project_common` 迁移。
- 刷新 GitLab 列表使用管理员浏览器中保存的令牌或账号密码。支持跨域的 HTTPS GitLab 可直接访问。内网 HTTP 或跨域受限的实例可在服务端用 `REVIEW_GITLAB_URLS` 设置允许中转的完整 GitLab 地址（逗号分隔）。中转只读取项目列表，登录资料经加密请求传入并在请求结束后丢弃。实例禁用密码授权时，可使用有读权限的访问令牌。
- “审查记录”的日历按日报生成日期选择，日报内另列提交日期。问题加入点击者上海时区当天的任务列表，同一个问题只添加一次。添加后由任务当前负责人或管理员维护问题的状态和备注。跨周追加复制会把关联移到新一周，忽略的问题不进入未完成任务复制。
- 任务转交会通知接收人。审查日报会通知有问题的已匹配提交人，无名氏问题或覆盖异常会通知管理员。管理员可在消息中心切换到“所有人员”查看状态。
- 保持周报页面打开即可实时更新消息和未读数。在支持网页通知的浏览器中，从“消息中心”点击“开启桌面通知”并授权，随后收到的消息可从系统通知跳转到当前周报标签页。部署需应用 `0011_notification_events` 迁移。

### Hermes 定时写入

后端部署时执行 `alembic upgrade head`，并在 Compose 的 `.env` 配置独立随机值 `REVIEW_WORKER_TOKEN`。在 Hermes 的 `.env` 配置相同的 `REVIEW_WORKER_TOKEN` 以及 `REVIEW_SYSTEM_URL`（周报系统的 HTTPS 页面根地址，生产地址保留 `/zhoubao` 前缀）。本机测试可以使用回环 HTTP 地址。

定时脚本用本机 `REVIEW_GITLAB_URL`、`REVIEW_GITLAB_TOKEN` 读取 GitLab（需要读取 API 和克隆仓库权限）。已有旧任务的电脑默认复用用户目录下 `code-review/daily_fetch.py` 中的 GitLab 设置，也可通过 `REVIEW_GITLAB_LEGACY_SOURCE` 指定旧配置路径。OCR 使用本机 CLI 配置，可用 `REVIEW_OCR_PATH` 指定可执行文件。浏览器登录资料与定时任务独立。

将 `scripts/zhoubao_daily_review.py` 复制到 `HERMES_HOME/scripts` 后，已有任务可用 `hermes cron resume <任务 ID>` 启用。首次注册可运行：

```sh
hermes cron create "30 8 * * *" --name daily-open-code-review-zhoubao --script zhoubao_daily_review.py --no-agent --deliver local
```

脚本使用上海时区前一自然日的提交时间，按项目和 SHA 去重。待写入的日报暂存在本机 `REVIEW_WORK_DIR`（默认用户目录的 `zhoubao-review`），失败后下次优先重投。需要重新审查时，可为脚本传入 `--report-date YYYY-MM-DD --rebuild`。正面评价依据实际增加或更新的测试文件和项目文档生成，审查覆盖异常会列在日报内。

若同时保留旧 HTML 日报，采集和漏审检查分别使用同目录的 `zhoubao_legacy_review_scope.py fetch` 和 `zhoubao_legacy_review_scope.py check-missed`。两者都通过周报任务接口读取启用的项目及各项目的分支过滤设置。调用时可沿用 `REVIEW_SYSTEM_URL` 和 `REVIEW_WORKER_TOKEN`，或用 `--system-url` 和 `--config` 指定部署地址及包含任务令牌的本地文件。

登录、修改密码、新建用户及重置密码的请求体均采用加密凭据：客户端从 `/api/auth/public-key` 获取当前进程的 RSA 公钥，以随机 AES-256-GCM 密钥加密整个 JSON 表单（请求路径作为认证附加数据），再以 RSA-OAEP/SHA-256 加密 AES 密钥。接口只接受 `key`、`iv`、`data` 三个 Base64 字段，不接受明文密码字段；数据库仍使用 Argon2 哈希存储密码。服务重启后公钥会更新，客户端每次提交都会重新获取。

**对外部署必须通过 HTTPS 提供网页和 API**，在 TLS 入口终止 HTTPS，并将流量转发到容器内的 Nginx。浏览器加密不能保护通过 HTTP 下发的网页免遭篡改。`compose.server.yaml` 已启用 `COOKIE_SECURE=true`，因此正式站点必须使用 HTTPS；本机 `127.0.0.1` 开发环境可继续使用 HTTP。

## 发布版本号

登录后的侧栏版本号读取 `frontend/package.json` 的 `version`。鼠标悬停、点击或键盘聚焦侧栏版本号时，默认显示当前版本的更新说明。可用左右箭头按版本号查看历史，按 Esc 关闭。本次版本为 `3.0.0`。

发版说明省略引导功能相关的改动。每次生产发版先将变更描述写入一个 UTF-8 文本文件，再从仓库根目录执行：

```sh
python scripts/prepare_release.py 1.2.6 --notes-file release-notes.txt
```

该命令同时更新前端版本号、锁文件、`backend/releases.json` 和生产 API / Web 镜像标签。同一版本的说明不能修改，新变更使用新版本号；历史记录不覆盖。

准备完成后，按生产部署流程构建并部署 **API 和 Web 两个镜像**。API 启动依次执行数据库迁移、发版记录入库、启动服务；更新内容写入 `release_records` 表，唯一版本号确保重复启动不重复记录。以后每次生产发版都需要更新 API 镜像，使本次说明自动入库。仅更新 Web 镜像会遗漏新版本的发版记录。

生产 API 和 Web 健康检查、页面版本及发版记录都核验通过后，在生产目录执行以下命令，向仍打开旧版本的用户推送右下角的「有新版 v2.4.0 已就绪」提醒。把示例版本替换为本次发布版本。

```sh
docker compose -p zhoubao-server -f compose.yaml -f compose.server.yaml exec -T api python -m app.release_announcement 2.4.0
```

命令可以安全重试，同一版本只发布一次。已加载新版本的页面跳过提示，仍在运行旧版本的页签重新连接后也能补收。「刷新页面」重新加载当前页签，「稍后」关闭该页签的本次提示。已授权桌面通知时，点击发版通知会返回周报系统并显示右下角提示。旧客户端通过普通系统消息兼容桌面提醒，补收窗口为十分钟。迁移 `0017_release_announcement` 保存实际通知时间。

发版记录表由迁移 `0008_release_records` 创建。历史版本 `1.2.5` 的说明依据已有发版提交补录。测试环境使用独立数据库，也会在启动时导入随镜像提供的说明。

## 会议任务指派

- 会议关联任务使用“任务名称”“完成状态”，状态与本周工作一致；旧“未完成”迁移为“未开始”。
- 指派人员支持多选普通用户。新指派和转交都进入接收人的任务箱，消息会跳转并高亮对应卡片。开始任务后，周明细的来源图标可查看转交人或打开指派会议。
- 多人任务的名称在会议记录中统一维护。每人的本周任务进展独立保存，完成状态与会议记录中的个人状态双向同步。
- 取消指派、删除会议关联任务、关闭跟踪或删除会议记录时，系统移除相应卡片及本周关联明细，并保留历史明细。
- 部署需执行 `alembic upgrade head`，应用 `0018_task_plans_and_inbox` 迁移。
